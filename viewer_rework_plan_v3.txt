VIEWER REWORK PLAN v3
=====================

Purpose
-------

Replace the current patchwork viewer engine with one strict, inspectable build
path while preserving the useful input adapters, project prompts, browser UI,
ROI/threshold editors, mailbox workflow, figure controls, and reusable assets.

The first implementation target is the normal DAS path:

  current df/obs/dfxy
    -> existing project config and prompts
    -> exact slide_scene manifest
    -> one fresh run plan
    -> one writer
    -> one ready viewer

Do not make a temporary viewer and read it back. Do not use viewer_data.json as
an input to another run. Do not add classes or a second viewer runtime.

The current scripts are backed up by the user. This pass may remove obsolete
internal compatibility machinery aggressively. Existing generated HTML files
must not be modified or deleted.


Hierarchy Of Truth
------------------

These sources are useful, but they are not peers.

1. Current DAS triplet

   - obs["slide_scene"] is the authoritative spatial identity in standard DAS
     mode.
   - df, obs, and dfxy indexes must be unique and exactly aligned.
   - Current obs annotations, not a previous viewer, define grouping, subsets,
     ROI rows, and overlays.

2. Existing project config

   - Stores user choices such as figure roots, segmentation roots, viewer
     output root, and asset source inputs.
   - Keep the current project-config files, inheritance, prompts, GUI transport,
     and shared path parsing.
   - Config says where to look. It does not override triplet identity.

3. Ephemeral scene_manifest

   - Constructed once for the current run.
   - Keyed only by complete slide_scene values.
   - Contains resolved channels, exact segmentation TIFF, display label, and
     any layout hint.
   - This is the only spatial object accepted by the engine.

4. Asset registry and overlay cache

   - Performance aids only.
   - Reuse requires an exact slide_scene and a valid input signature.
   - Missing, stale, incompatible, or ambiguous cache entries are ignored and
     regenerated. They never alter current scenes or annotations.

5. Run outputs

   - viewer_data.json, sidecars, and HTML are outputs only.
   - They are never consulted to decide what a new run contains.

Standalone adapters sit before item 1. They may construct a triplet and a
slide_scene manifest, but the fallback must be explicit and loud. The core
engine itself never infers identity.


Canonical Dicts
---------------

Use four ordinary dictionaries. Do not introduce dataclasses or stateful
builder objects.

project_context
  Existing resolved user/config values. Keep current key names where possible.

scene_manifest
  {
    "BTK153ROI01": {
      "slide_scene": "BTK153ROI01",
      "display_label": "BTK153 ROI01",
      "channel_sources": [...],
      "segmentation_tif": ".../label_BTK153_ROI01.tif" or "",
      "source_paths": [...],
      "layout_hint": {}
    }
  }

run_plan
  Current-run facts computed from the triplet and manifest: included scenes,
  core tile specifications, groupings, views, subset definitions, ROI payload
  specifications, threshold payload, figure sources/associations, and output
  naming. It contains no state copied from an old viewer.

build_report
  {
    "status": "building" | "ready" | "failed",
    "scenes": {...},
    "features": {
      "core_images": {...},
      "roi": {...},
      "threshold": {...},
      "subset_overlays": {...},
      "figures": {...}
    },
    "warnings": [...],
    "errors": [...]
  }

Each major function accepts a dict and returns a dict. Avoid ambient globals.


One Public Engine Handoff
-------------------------

Add one engine-facing function in visualization/call_visu_html_7.py:

  build_viewer_run(
      df,
      obs,
      dfxy,
      scene_manifest,
      project_context,
      roi_mailbox=None,
      threshold_store=None,
      run_options=None,
  )

Behavior:

1. Validate the triplet and scene manifest without writing.
2. Build and print a complete preflight/run_plan.
3. Stop before expensive work if required inputs are invalid.
4. Ask only about known optional degradation, such as unresolved masks or
   skipping figures.
5. Call one writer in visu_html_functions7.py.
6. Return a result dict containing exact html_path, viewer_data_path,
   build_report_path, run_dir, and status.

cvh.main() remains a thin Metro/CLI-compatible wrapper. It resolves existing
prompts and adapters, calls build_viewer_run(), updates the existing meta sink,
and returns the original df/obs/dfxy tuple.


Required, Optional, And Cacheable Work
--------------------------------------

Required for a valid run:

- aligned df/obs/dfxy
- nonblank exact obs.slide_scene in standard DAS mode
- one accepted image/channel set per included scene
- writable run directory
- core viewer_data.json and viewer HTML

Feature-required, but not fatal to the core viewer:

- ROI rows and ROI runtime for ROI controls
- threshold rows/store and threshold runtime for threshold controls
- subset overlays for overlay display

If one feature fails, record the failure and disable that feature. Do not
pretend it is available and do not discard the core viewer.

Optional:

- figures
- segmentation boundaries when the user accepts centroid fallback
- layout hints and display refinements

Cacheable:

- normalized channel PNGs
- copied portable figures
- subset overlays
- extracted cell boundaries
- asset registry entries

I/O Failure Policy
------------------

Figures:

- no 90-minute retries
- FileNotFoundError, PermissionError, EPERM, EACCES, invalid image, or invalid
  destination: skip immediately and record source path plus error
- at most a short bounded retry for explicitly transient network errors
- one failed figure never prevents READY

Required core writes:

- use atomic temp-file replacement
- short bounded retry for transient network errors
- permissions/path-policy errors fail the run immediately with the exact path
- no catch-all conversion to "asset not found"

Update support/filesystem_utils.py only by adding an optional retry predicate
or explicit attempt limit. Preserve default behavior for unrelated callers.
The viewer must pass its stricter policy explicitly.

Stop Conditions During Implementation
-------------------------------------

Stop and reassess rather than patch around any of these:

- a standard DAS run reaches the engine without obs.slide_scene
- an adapter cannot produce one exact manifest record per scene
- browser JS requires a field that has no clear current-run owner
- an optional feature must mutate core scene identity
- cache reuse cannot be validated without consulting previous viewer_data
- a proposed compatibility path would create a second build engine

The desired end state is not "all failures hidden." It is that a failed gear
has one visible seam, optional features fail independently, and current data
always controls the run.
