================================================================
1. WHAT THE SCRIPT TRANSFERS
================================================================

Use "transfer_display_settings_v2.groovy" inside QuPath 0.7.0 to
copy display settings from one image to another image, or to every
image in the current project.

The script transfers:

  - Brightness/contrast intensity ranges for each channel
  - Whether each channel is on or off
  - Channel colors

The script does not edit annotations, detections, measurements, or
analysis results.

By default, v2 assumes exact channel-name matches:

  def MATCH_MODE = "EXACT"

This is the preferred mode when the full QuPath display channel names
match across images. There is also a legacy marker-matching mode:

  def MATCH_MODE = "MARKER"

MARKER strips prefixes such as NK_SCREEN_B171_C02R2_ and matches by
the marker name. Use it only if exact channel names do not match.


================================================================
2. QUICK WORKFLOW
================================================================

  1. Open the source image in QuPath.

  2. Adjust the Brightness & Contrast panel until the image looks
     the way you want.

  3. Run the script in CAPTURE mode.

  4. To update one currently open image, run APPLY.

  5. To update every image in the current project, run APPLY_ALL.

Run the script with the normal Run button in QuPath's script editor.
Do not use "Run for project"; APPLY_ALL handles the project loop
itself.


================================================================
3. SAVING SETTINGS FROM ONE SLIDE (CAPTURE)
================================================================

CAPTURE reads the display settings you are currently looking at in
the QuPath viewer. It is okay if the display settings have not been
saved yet; CAPTURE is intentionally based on the live viewer state.

Steps:

  1. Open the source slide.

  2. Open Brightness & Contrast:

       View > Brightness & Contrast

     or press Shift+C.

  3. Adjust channel min/max ranges, channel on/off checkboxes, and
     colors.

  4. Open:

       transfer_display_settings_v2.groovy

     in QuPath's script editor.

  5. Set the top of the script:

       def MODE = "CAPTURE"
       def PRESET_NAME = "default"
       def MATCH_MODE = "EXACT"

     Change "default" to any useful preset name.

  6. Click Run.

The preset is saved in the current QuPath project folder:

  saved_display_presets/default.json

The log will list every captured channel, whether it is on or off,
its min/max range, and its color.


================================================================
4. APPLYING SETTINGS TO ONE OPEN SLIDE (APPLY)
================================================================

APPLY updates only the currently open image.

Steps:

  1. Open the target slide in QuPath.

  2. Set the top of the script:

       def MODE = "APPLY"
       def PRESET_NAME = "default"
       def MATCH_MODE = "EXACT"

  3. Click Run.

The image display updates immediately. If colors changed, the script
updates the image server metadata for the current image. Save the
image/project in QuPath if you want this single-image APPLY persisted.


================================================================
5. APPLYING SETTINGS TO EVERY PROJECT IMAGE (APPLY_ALL)
================================================================

APPLY_ALL applies the captured preset to every image entry in the
current QuPath project.

This is the main v2 change: APPLY_ALL does not open each image in the
viewer. It reads each project entry's ImageData, applies the display
settings through QuPath's ImageDisplay API, and saves that same entry.

Steps:

  1. First run CAPTURE on the reference slide.

  2. Set the top of the script:

       def MODE = "APPLY_ALL"
       def PRESET_NAME = "default"
       def MATCH_MODE = "EXACT"
       def BACKUP_BEFORE_APPLY_ALL = true
       def DRY_RUN = false

  3. Click the normal Run button.

APPLY_ALL will:

  - Create a timestamped backup if BACKUP_BEFORE_APPLY_ALL is true
  - Loop through project.getImageList()
  - Read each entry with entry.readImageData()
  - Apply min/max and visibility through ImageDisplay.create(imageData)
  - Apply colors through imageData.updateServerMetadata(...)
  - Save with entry.saveImageData(imageData)
  - Sync the project at the end

Backups are written inside:

  backups/pre_transfer_display_v2_YYYY-MM-DD_HHMMSS/

Existing backups are not copied into the new backup.


================================================================
6. OPTIONS AT THE TOP OF THE SCRIPT
================================================================

MODE
----

  def MODE = "CAPTURE"

Allowed values:

  CAPTURE    Save display settings from the open viewer.
  APPLY      Apply a preset to the currently open image.
  APPLY_ALL  Apply a preset to every image in the current project.


PRESET_NAME
-----------

  def PRESET_NAME = "default"

The preset file is stored as:

  saved_display_presets/default.json

Use different names for different display styles, for example:

  TLS_view
  full_panel
  CD3_B220_H3


MATCH_MODE
----------

  def MATCH_MODE = "EXACT"

EXACT matches full QuPath display channel names. This is preferred
when channel names match across slides.

  def MATCH_MODE = "MARKER"

MARKER strips the staining prefix and matches by marker name. This is
only for projects where the same marker has different full names on
different slides.


BACKUP_BEFORE_APPLY_ALL
-----------------------

  def BACKUP_BEFORE_APPLY_ALL = true

When true, APPLY_ALL backs up the project folder before saving any
changes. Leave this on unless you have already made your own backup.


DRY_RUN
-------

  def DRY_RUN = false

Set this to true to test matching and logging without saving changes:

  def DRY_RUN = true

Dry runs do not create backups because they do not write changes.


================================================================
7. NOTES AND TROUBLESHOOTING
================================================================

Use normal Run, not Run for project.

If APPLY_ALL reports skipped channels:

  - In EXACT mode, skipped means the channel name was not present in
    the captured preset.
  - Check whether the displayed channel names include suffixes like
    "(C1)".
  - If exact names really differ by slide, use MATCH_MODE = "MARKER".

If CAPTURE saves the wrong settings:

  - CAPTURE records whatever the viewer is currently showing.
  - Re-adjust the Brightness & Contrast panel and run CAPTURE again
    using the same PRESET_NAME to overwrite that preset.

If APPLY updates the display but not after reopening:

  - Single-image APPLY modifies the open image.
  - Save the image/project in QuPath after APPLY if you want that
    single-image change persisted.
  - APPLY_ALL saves each project entry automatically.

If you want to inspect a preset:

  - Open the JSON file in saved_display_presets/.
  - Each channel entry stores name, serverName, min, max, show, and
    color.


================================================================
8. METHODS
================================================================

QuPath stores display state in two places:

  - Channel colors are part of image server metadata.
  - Min/max display ranges and channel visibility are stored in
    ImageData properties under QuPath's ImageDisplay property.

CAPTURE uses the open viewer:

  viewer.getImageDisplay()
  imageDisplay.availableChannels()
  imageDisplay.selectedChannels()

For each channel, CAPTURE records:

  - ch.getName()
  - ch.getMinDisplay()
  - ch.getMaxDisplay()
  - selected/not selected
  - ch.getColor()

APPLY_ALL avoids GUI image switching. For each project image entry,
it uses:

  entry.readImageData()
  ImageDisplay.create(imageData)
  imageDisplay.setMinMaxDisplay(...)
  imageDisplay.setChannelSelected(...)
  imageData.updateServerMetadata(...)
  entry.saveImageData(imageData)
  project.syncChanges()

This avoids the old viewer-loop approach:

  qupath.openImageEntry(entry)
  getCurrentViewer()
  viewer.setImageData(...)

Those viewer-based project loops caused save prompts, JavaFX timing
issues, and project-entry mixups. The v2 APPLY_ALL path keeps each
entry paired with its own ImageData from read through save.
