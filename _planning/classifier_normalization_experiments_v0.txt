Existing architecture and missing controls
-----------------------------------------
home.classifier is a replayable action and GUI entry, with named mode, sources,
checkpoint, output_root, training and inference answers. Both routes call the
same run_project.main/engine. Sources are a list, allowing mixed triplet/CSV and
manifest data with the existing three semantic channels and four output classes.
train_test starts fresh; tune_test loads parent weights with a fresh optimizer;
predict never trains. Each run produces a unique output folder and recipe record.

Current exposed recipe controls do NOT yet include lower percentile, configurable
normalization policy, persistent shared cache reuse, or report verbosity. Setting
error_gallery_limit changes cells per page, not the number of errors exported.
Parent predict/tune paths inherit preprocessing from the checkpoint; a changed
policy must be explicit and saved with each freshly trained model/checkpoint.

Avoid advertising proposed fields as runnable recipe syntax before implementing
the action, pure validation, engine propagation and save/reload handling.

Local staged images vs normalized arrays
---------------------------------------
Staging holds resampled but unnormalized marker TIFFs, integer masks, labels,
scene metadata and ingest provenance. These can be reused across normalization
experiments at the SAME working resolution. Changing pixel size/channel source
requires a separate staging identity. Re-reading originals may be needed for a
different resampling grid; repeatedly resampling a lossy working image is not an
equivalent replacement for going back to its source.

normalized_cache holds already transformed marker arrays, masks and an index.
These arrays are not generally reusable under changed normalization: clipping
loses information. Recompute normalized values from the unnormalized staged TIFFs.
No network re-download or new copy of staged TIFFs is inherently necessary.
The manifest adapter already bypasses restaging, but the ordinary launcher still
creates a new per-run normalized cache. streaming.open_cache can read an existing
index; automatic validated cache selection is not exposed through the recipe yet.

Measured CycIF pilot disk allocation (MiB):
  dataset (unnormalized staged inputs): 155.2
  normalized_cache:                    155.0
  test (PNGs, tables, galleries):        97.1
  root run records:                      1.6

Recommended extension: shared immutable staged sources, normalized caches keyed
by source identity/resampling/channel selection/normalization policy, and unique
run folders containing references, models, metrics, tables and requested previews.
Masks need not be copied for each intensity policy. Short experiments may compute
normalized arrays in memory from local staged images rather than persist a new
full normalized cache. Training can reuse a policy-specific cache over epochs.
Never reuse a clipped array for a different policy or change a historical cache
in place. Cache lifetime/dependencies must be tracked before deleting run folders
currently hosting inputs used by later manifests.

Separate split/label metadata from reusable image arrays. In particular, the
CycIF pilot scene is currently test; using its same images for development/train
requires a new lightweight scene/split record and training coverage windows,
without editing the old scene or copying all its TIFFs again.

Normalization experiment controls to add before heavy execution
--------------------------------------------------------------
Expose explicit lower/upper percentile policy and reference pixel population
through the recipe; preserve the current zero-background/99.5-positive-percentile
default for old checkpoints. Candidate comparisons: current policy, P50-P99.5,
and P50-P95, with identical training ROIs, seed, epoch budget and class handling.
Decide/reference tissue pixels consistently; no per-cell or per-tile stretching.
The learned model must see the same policy during training and inference.

Expose lightweight reports: metrics/all-cell CSV + bounded previews by default
for experiments; exhaustive galleries opt-in. Keep enough configuration/source
provenance and fitted normalization statistics for exact interpretation.
Keep GUI and recipes on the same action; do not introduce another experiment
runner or a classifier-specific config/path persistence system.
