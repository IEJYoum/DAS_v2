General:
The overall idea was to make the classification problem as easy as possible and as cross-panel/lab/platform friendly as possible. This makes it easier to collect training data and will make the final product better for a broader pool of users.

Architecture:
I wanted to use a CNN so it can learn morphology features and notice how a signal looks different when it originates from a cell vs bleedover from nearby cells (i.e. symmetrical vs non). Also to be able to consider whether a cell is much dimmer than its neighbors (an immune cell in a nest) even if there's symmetrical signal. Also it's just the right tool for ML on images.
I train an encoder simultaneously because.. well it seems ML to get a distilled information vector. It'll be worth testing an independently-trained encoder.
The goal is to test out different combinations of ML machinery (encoder vs non, MLP vs CoE, etc). I have a hypothesis for which engine might be best, but it's much better to build a system that allows for empirical comparison of architectures than to just hope I pick the perfect one on the first try.

Classification vs. binary labels:
I decided to predict cell classes directly rather than binaries because that can learn 'this is an immune cell in a tumor nest' more cleanly than 'this cell with PanCK+ isn't actually a tumor cell because its signal is slightly lower than that of surrounding cells.' It also solves two problems at once- if we only predicted binaries per-marker, we'd still have to classify cells that had unusual combinations of positives. Also, for collecting a training set I'm relying partly on manual gating/classification; our binary classes don't really aim to ID 'is this signal real expression from this cell' while the classes do aim to ID 'this cell is an immune cell.' The other sources of "truth" I have are weight-based classification and clustering classification; neither of these produce binaries and both aim to sort cells with conflicting signals. For future training sets I intend to use public data and data from other labs running other assays. There is a standard definition of a given cell phenotype - meanwhile deciding that something is signal rather than noise is subjective and the method will change from lab to lab, degrading the fidelity of training sets and making the tool much less useful to a lab whose strategy requires a different standard. Finally, by learning cell classes, the model can begin to learn morphology and spatial features (hypothesis). If we use the CoE model, it will be possible to train an expert purely on morphology using a brightfield stain, or to train an expert on H&E stains and include them as optional assistants (with their own input heads, I think?) when labs have access to their expected features. But even without this, I expect the CNN to begin to recognize features like size and shape (though we have to discuss how this might clash with inconsistent segmentation practices and the way in which data is sampled outlined below).

Loss and weights:
I did not want the model to learn to predict background - this would require a large portion of the model to learn 'is this a cell.' I already have a CNN that's learning to predict cell boundaries; I don't see any benefit to duplicating that challenge here. So, the model requires a segmentation mask as input, and it trains with the loss weight set to zero outside cells. This makes the problem much easier - given that this pixel is part of a cell, which type of cell does it belong to? It also increases the density of the training sets - they're not mostly background/noise, they're all cells, so what would be the largest prediction class (background) is removed from the problem, which of course makes prediction much easier without sacrificing any signal. The CNN can still consider pixels outside cells (via convolution) to assist with prediction, it just doesn't train on them.
Because there's still significant class imbalance, I'm scalling loss by class prevalance (with a cap - though results suggest this cap needs to be raised/removed- another example of evidence driven design).

Inputs:
Both to make the classification problem easier and more generalizable, we're training the model to recognize 'supersignals' rather than on bespoke combinations of proteins. We allow users to specify which combination of markers they want the model to see as the 'immune' stain, as the epithelial stain, etc. As the architecture improves, the framework will easily allow us to re-train (or potentially add a new input head and tune?) models to identify more classes e.g. immune/tumor subtypes. This makes the problem much easier - the model sees one signal per class. It will also make the product much more useful - it means the model will be useful to any panel that includes a minimum number of features (at least one immune stain, at least one epithelial stain, etc.). The architecture still allows for greater specialization (train/tune a new model with more detailed inputs), but unlike my previous failure at a similar design, it doesn't require it. This will also make it much easier to procure training data from a variety of sources.

Results so far:
Training the model to predict 4 classes (imm, epi, artifact, other) on just 1 ROI (22,597cells) took roughly 3 minutes and allowed it to predict cell classes in 3 other ROIs from the same staining batch to 94% accuracy. This batch had worse-than-average stain quality for our lab. Remarkably, when the same trained model was applied on a forward pass to another batch/panel of data (same immune and epithelial stain, different nuclear stain), it was able to predict labels for two classes (immune and epi) at 96% accuracy! Without any tuning/retraining. There was some significant variance here - one ROI in that batch was nearly 100% correct while another was closer to 80%. This is obviously a much easier problem than predicting granular subtypes, the stains have been pretty consistent from just one lab (we haven't tried to capture mIHC PanCK and CycIF Ecad stains together), and it's generally failed to identify artifacts (though this will actually benefit from having more granular inputs/classes since it currently only sees immune+epi superstains, and many immune cells are imbedded in tumor nests and look double positive without being artifacts). Clearly these results are very prelimiary and a long ways off from a useful cross-assay cell classification tool, but I find them very encouraging.

Other pieces of the architecture that sort of bubbled up during planning/implementation rather than being the central idea I brought to the table (though ofc I did 'orchestrate' them, to use the language of one of the papers I read):

Normalization precedes superstain construction. Each marker is normalized on its complete ROI using background subtraction, the 99.5th percentile of positive intensities, and clipping to [0,1]. Markers within a semantic group are combined by pixelwise maximum. There are three inputs—nuclear, immune and epithelial—not one input per output class. Artifact and other-cell calls have no dedicated stain channel. This abstraction also discards individual marker identity.
Cell-size weighting is separate from class balancing. Each labelled cell’s pixels receive inverse-area weights, so large cells do not dominate simply by containing more pixels. Class multipliers then use unique training-cell counts, capped at five. Background and unlabelled cells have zero loss. Raising the cap is a sensible experiment, but artifact failure alone doesn’t establish that it is the solution: the baseline had only 14 artifact-labelled training cells. Training uses aligned rotations/flips and marker dropout. Marker dropout selects nonempty subsets within nonnuclear superstains. Physical scale is standardized to 0.5 µm/px, subject to recorded source-scale assumptions.
Tiles preserve ROI identity and complete cells. An ROI belongs to one split. A cell supervises a training tile only when its entire mask fits inside it. Inference covers the complete ROI with overlapping tiles, averages overlapping probabilities, then averages probabilities within each cell before selecting its class. It does not majority-vote hard pixel labels.
“Other” and “unlabelled” are different. BCC Other Cells/aSMA+ now affirmatively supervise the existing UNCLASSIFIED output. Missing CSV labels remain ignored. Every segmented cell receives a prediction; there is no abstention rule. certainty is an uncalibrated probability summary.
Segmentation practice still affects classification. Although outlines aren’t CNN inputs, masks determine supervised regions and probability pooling. Nuclear versus whole-cell masks, merged objects and different boundary conventions can therefore change results.
Validation selects weights by macro-F1, not accuracy. We also implemented frozen parent checkpoints, fine-tuning with a fresh optimizer, old-training replay, reproducible split/config records, bounded image memory and checkpoint/export consistency checks. These make experiments comparable; they don’t themselves establish biological validity.
