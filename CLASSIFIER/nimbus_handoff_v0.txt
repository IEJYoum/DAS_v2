Nimbus / DAS CLASSIFIER handoff v0
==================================

Purpose
-------
Assess and propose the smallest safe Nimbus integration that reuses the
CLASSIFIER's image-plus-mask input mechanics without making Nimbus pretend to
be the existing lineage CNN.

Current orientation
-------------------
The CLASSIFIER and Nimbus need the same physical inputs per ROI:

  * named multiplex image planes;
  * one 2D integer whole-cell segmentation mask on the same pixel grid;
  * a stable ROI identity (DAS: slide_scene);
  * cell identity equal to the mask label within that ROI.

The existing CLASSIFIER scene contract already records most of this in
scene.json: scene_id, markers, mask, pixel scale, and source metadata. It is
strong evidence that a shared scene-inventory layer is worthwhile.

However, do NOT put Nimbus inside the existing CNN's train/predict modes.
Those modes assume three ordered superstain groups, four fixed lineage
classes, CNN checkpoint schema, and cells.csv labels. Nimbus has a different
model/checkpoint and needs no training labels for inference. Reusing
CLASSIFIER.adapters.stage unchanged would therefore force fake labels and
create brittle coupling.

Requested design
----------------
Propose a minimal, additive Nimbus branch that rhymes with the CLASSIFIER
rather than forks DAS infrastructure.

1. Reuse now
   * support.image_sources for TIFF/OME channel inspection and channel specs.
   * support.ingest_sources, support.path_compat, project-config path prompts,
     controller io/recipe plumbing, and output-folder/provenance conventions.
   * the established identity rule: join returned per-cell results on
     (slide_scene, mask_label/cell_id), never dataframe row order or cell ID
     alone.

2. Extract only a small generic seam if it demonstrably removes duplication
   * Candidate: a label-free source-scene inventory/manifest containing
     scene_id/slide_scene, explicit marker paths or ChannelSource specs, mask
     path, pixel scale, and source signatures.
   * Keep CLASSIFIER's cells.csv, split allocation, label mapping, superstain
     construction, tile supervision, and CNN checkpoint code classifier-only.
   * Existing classifier scene.json can be an accepted input format, but Nimbus
     must not require cells.csv or train/val/test splits.
   * Do not perform a broad manifest redesign before one real Nimbus proof run.

3. Nimbus runner contract
   * Implement as a separate Nimbus environment/runner called from DAS with
     explicit JSON settings, not an import that contaminates the DAS env.
   * One output run folder per invocation, e.g. project/nimbus/run_<stamp>/.
   * Record resolved image/mask mapping, requested channels, resolved channel
     names, model/checkpoint version, package version, normalization settings,
     device, and exact output paths.
   * Run preflight before the expensive call: readable files, unique scene IDs,
     2D integer masks, matching image/mask dimensions, no duplicate marker
     names, and output cell identity coverage.
   * Initial import should be additive: retain raw DAS intensity df unchanged;
     import Nimbus values under explicit nimbus_ prefixes after coverage checks.

4. Menu/recipes
   * Add a separate action such as home.nimbus or home.marker_positivity; do
     not add it as another CLASSIFIER mode.
   * It should use the same recipe mechanism as home.classifier: named answers,
     GUI/CLI/headless parity, and one controller call.
   * Recipe fields should remain operational rather than aspirational: source
     scenes/paths, mask mapping, selected marker channels, output root, device,
     and a pinned model/version choice. Do not expose every Nimbus tuning knob
     on the first pass.

5. Validation gates
   * First run on one known ROI only.
   * Verify that every Nimbus output cell has exactly one DAS counterpart by
     (slide_scene, mask label), and fail rather than silently dropping cells.
   * Inspect marker-level agreement/QC against current threshold calls before
     exposing batch operation.
   * Decide explicitly whether DAPI, autofluorescence, QC, and morphology
     channels are inputs, excluded channels, or marker context. Never silently
     pass every TIFF in a folder.

Questions for the CLASSIFIER agent
----------------------------------
A. Is there an existing reusable, label-free scene inventory seam hidden in
   CLASSIFIER/adapters.py or prepare_* that can be promoted with <~100 lines,
   without perturbing current CNN training/inference?

B. If not, should Nimbus initially own a tiny adapter that writes/reads an
   explicit Nimbus scene mapping and only later extract a shared helper after
   its real-data proof? Prefer this if it avoids touching validated CNN code.

C. What exact current controller/recipe changes are needed to add a standalone
   action without destabilizing the existing classifier action? Note:
   startup_prepare_data currently displays "CNN cell classification" but its
   functions list shown in controler.py does not include startup_cell_classifier.
   Confirm whether this is a live dispatch bug before attaching Nimbus nearby.

D. Define the narrowest test fixture: two small image planes + integer mask,
   no cells.csv, then mocked Nimbus output with repeated local IDs across two
   scenes. It must prove scene-qualified joins and failure on missing/duplicate
   output IDs.

Non-goals
---------
* No replacement of the existing CNN.
* No LLM/agent decision layer.
* No forced conversion/copying/renaming of source images.
* No broad recipe-framework work.
* No final biological cell-type claims from Nimbus alone: Nimbus is expected to
  supply image-aware marker calls/scores for later DAS phenotyping/clustering.

Direct answers to A-D
---------------------
A. There is no complete, model-neutral CLASSIFIER inventory API ready to promote
   unchanged. CLASSIFIER/adapters.one_match is small path-pattern glue, but
   resolve_sources also knows marker_groups/NUC and stage invokes label ingest,
   resampling and training windows. source_inputs.preflight owns split/replay
   policy. None is the label-free Nimbus entry point you want.

   A useful additional example is data_extraction/feature_extraction_recipe.py:
   preflight assembles label-free jobs with slide_scene, nucleus, cell, markers
   and input metadata. It consumes completed AF results plus explicitly named
   raw markers. This is closer to the desired seam than classifier stage, but
   still owns feature-extraction-specific requirements (two mask roles, corrected
   marker policy, filename conventions). Reuse its helpers/pattern, not its
   entire function as a mandatory Nimbus dependency.

B. Start with a thin Nimbus adapter accepting explicit source-scene mappings,
   using the shared owners listed below. This is an appropriate consumer adapter,
   not permission to implement another path/TIFF/config stack. For the first real
   ROI, an explicit mapping is enough. Only extract a common inventory assembler
   after a second real consumer demonstrates the same semantics. Pure one-file
   pattern resolution could be factored later without changing CNN normalization,
   labels, splits, checkpoints or training code. Do not import CLASSIFIER just
   to allocate directories or read TIFFs.

C. The suspected Prepare Data dispatch bug is NOT present in this checkout:
   controler.startup_prepare_data has aligned option/function entries; slot 6
   dispatches lambda state: perform_action(state, 'home.classifier').
   tests/test_classifier_recipes.py::test_prepare_menu_classifier_slot_calls_registered_action
   covers it. It is an intentional registered-action call, not a missing direct
   startup_cell_classifier function reference. Recheck the other WS's checkout.
   Exact Nimbus action/menu changes are described below.

D. Use two scenes with the SAME local IDs (e.g. 1 and 2), two nonconstant marker
   planes per scene, and background ID 0. Shuffle output rows and the triplet
   index to prove the identity join. No cells.csv or truth labels. Require
   duplicate/missing/extra scene-marker-object outputs to fail under the chosen
   coverage contract. Missing requested markers and wrong image/mask shapes
   also fail before the subprocess. A mocked Nimbus child is sufficient for
   DAS integration tests; one real ROI proves the actual model boundary.

Existing shared machinery: use these actual owners
-------------------------------------------------
Path and source selection:
  support.path_compat.resolve_native_path/native_path_text: validate native path
  forms before I/O. Windows UNC and Linux mounts are not interchangeable by
  magic. Only configured/known aliases are translated; do not invent mappings.
  support.ingest_sources.expand_source_spec(..., want='files', base_dir=...):
  file/glob expansion; ** is recursive. A literal directory is not recursively
  scanned by this helper. prompt_source_specs and split/join_source_specs own
  routed collection and the existing || representation for multiple specs.
  Apply consumer selectors after expansion. Zero/multiple matches for a requested
  scene-marker pair require an explicit decision, not a first-file fallback.

Naming/conventions:
  support.image_conventions.parse_cycif_record, parse_feature_marker_record,
  normalize_marker_key, find_segmentation_pair, and
  resolve_registered_cellpose_sources already cover important registered CycIF,
  marker and Cellpose association cases. Extend naming rules here when needed,
  not in a Nimbus filename parser. Explicit per-scene mappings remain valid for
  unfamiliar layouts. Avoid accidentally selecting R1-Segmentation/test runs.
  find_segmentation_pair(..., strict=True, kind='cell'/'nucleus') constrains the
  Cellpose folder and role; inspect the returned selected filenames. Its cell
  resolution has documented suffix fallbacks, not a guarantee of one mask version.

TIFFs/channels/windows:
  support.image_sources.ChannelSource, inspect_image_source,
  channel_sources_from_info, channel_source_to_json/from_json, read_channel,
  materialize_channel_tiff and open_channel_window_reader/read_channel_window.
  A ChannelSource can represent an individual TIFF or an OME channel/series;
  indices are zero-based. Carry explicit channel metadata across the JSON bridge.
  Current resolve_channel can return a first matching name: enforce ambiguity
  checks at the adapter boundary instead of claiming unique resolution exists.
  Window reading has explicit unsupported-layout failures; do not promise bounded
  memory and silently decode a whole multichannel slide as a fallback.

Interaction/config:
  support.io_adapter.iget/iprint/dprint and progress helpers preserve terminal,
  GUI and DS transport/logging. Inject callbacks; do not reinitialize the route
  inside a library, use bare input, or create a second UI parser.
  support.shared_utils.checkChange(current, label, input_fn=io.iget) owns the
  use/change interaction and its GUI metadata. flexMenu collects repeated text
  entries; controler.menu_index owns numbered choices. Keep these distinctions.
  support.project_config.load_project_settings returns values AND origins;
  save_project_settings merges existing project config and accepts on_update;
  select_project_path validates through the same routed path prompt when enabled.
  OS profiles are project_config.txt and project_config_posix.txt, with inheritance.
  Explicit recipe answers override project defaults. Choose/document base_dir;
  for new recipes, paths relative to state.data_folder are the useful convention,
  not relative to the recipe file. Do not globally re-anchor legacy config keys.
  Controller saves should pass invalidate_project_config. New Nimbus keys, e.g.
  nimbus_python/nimbus_output_root, are proposals, not existing supported keys.

Publication:
  support.filesystem_utils.create_run_directory, atomic_write_json,
  atomic_write_with_retry; support.shared_utils.append_artifact_manifest_row.
  create_run_directory is already shared and avoids a Windows SMB private-ACL
  pitfall with tempfile.mkdtemp. Use it instead of copying CLASSIFIER.outputs.
  Native source signatures exist via image_sources.file_signature_for_source;
  these are stat/selection signatures, NOT content hashes or a complete cache key.

Mask role and grid: a critical correction to the opening orientation
--------------------------------------------------------------------
The current CNN accepts an object-label mask; it does not inherently require
whole-cell masks. The running VST_01.1 experiment uses the original nuc30
NUCLEUS basins because their IDs cover the saved triplet. Nimbus's appropriate
mask compartment is a Nimbus-side question: do not choose nucleus or whole-cell
just because the CNN used it. Record mask role, exact file/version and label
namespace explicitly in the source manifest and result.

On VST, the feature-extraction result already records both nucleus and expanded
matched-cell masks. Some matched-cell masks omit nucleus IDs still present in
the DAS triplet. Equality of image shapes or overlap at a few centroids is not
proof that masks have identical cell identity coverage. Require exact output
IDs versus the chosen input-mask IDs (exclude 0), then separately validate the
join into DAS. If only a subset is legitimately available, declare that policy
and write counts/missing IDs before inference/import; never silently intersect.
Unselected ROIs in a full triplet should remain present with blank new scores.

Retain pixel spacing, grid/frame, crop/origin/orientation and any resampling
transform in provenance. Registered TIFFs here have misleading 72-DPI tags and
no acquisition calibration. The original VS-TMA-17 R3 OME sidecar under
Cyclic_Images/d-vs.cmIF_2021-10-15_Panc/VS-TMA-17/original reports 0.325 um/pixel;
the current recipe records the assumption that registered images retain it.
Do not treat a DAS machine default as acquisition metadata for another dataset.

Use original images, not the classifier's scientific preprocessing
-----------------------------------------------------------------
No raw-image recopy/renaming is required. Each selected marker can resolve to
an independent path/ChannelSource; a common dataset root plus per-marker relative
patterns already supports mixed RegisteredImages and af_outputs layouts.
The completed AF result.json records plan.pairs with per-scene marker inputs,
selected references, correction settings and corrected output paths. The completed
feature-extraction result.json records scenes with nucleus/cell/markers/inputs.
These are useful resolved inventories. Read their actual schema rather than
guessing paths from an output folder name. Pin a specific AF run, not a wildcard
matching every historical correction.

Classifier artifacts also retain source_inventory.csv (source_markers/source_mask),
source_settings.json, input_settings.json, and per-scene ingest_report.json.
Use those ORIGINAL associations where useful. Staged CLASSIFIER TIFFs may already
be resampled, and normalized_cache is model-specific. Do not feed superclass
IMMUNE/EPI composites or the CNN's zero-floor/positive-99.5th-percentile scaling
to Nimbus by default. Preserve independent protein markers and let the pinned
Nimbus implementation own its required normalization. Record effective settings.
Treat DAPI, AF-reference and QC channels as explicit include/exclude decisions.

Triplet import/export and downstream use
---------------------------------------
controler.load_triplet/save_triplet are the established triplet boundary:
  df = numeric features; obs = observations/annotations; dfxy = coordinates.
The three share an aligned unique observation index (often slide_scene_cellid).
For strict additive export, load_triplet(..., normalize_labels=False,
strict_alignment=True) prevents normalization of existing truth and rejects
silent row intersection/reordering. Default align_triplet takes intersections,
so it is NOT a substitute for validating an external result's identity coverage.

DAS object IDs may live in df or obs, or in the index: make object_table and
object_column explicit. VST_01.1 has cellid='cell1' strings and numeric seg_label;
the correct numeric mask key is obs.seg_label, joined with obs.slide_scene.
Never parse a numeric suffix from a cell name or split a namespaced scene_id
back into a scene name. Include original_scene_id and dataset/source ID explicitly
if aggregating multiple datasets, plus the original DAS observation index in
the imported table. Cell ID 1 in two scenes must remain two different objects.

Suggested canonical worker output: long scene/object/marker rows with raw score
and optional call, preserving exact marker names and model/threshold provenance.
Require uniqueness on (dataset, scene, mask_label, marker). Do not call a score
a calibrated probability unless the pinned implementation actually guarantees it.
Validate requested marker coverage and finite outputs, then pivot/join by keys.
Missing results must remain missing or fail under the stated contract, never
become negative calls, zero intensity or an Other-cell truth annotation.

For initial pilot, publish annotation CSV(s), coverage/QC and optionally a NEW
saved triplet. Keep original intensity columns and existing biological labels.
Numeric nimbus_score_<marker> columns belong in a separate numeric table or
additive df columns for existing DAS analysis; categorical nimbus_call_<marker>
columns can go into obs. These names are proposed conventions. Do not overwrite
raw marker columns, DAS_unet_labels or Primary Celltype: Matrix. Collision policy
must be explicit. The classifier exporter demonstrates strict key joins, blank
unselected rows, a new stem and a small export.json, but its CNN_ naming/fields
must not become Nimbus's dependency. Factor only an actually shared join seam.

Existing IFA.importObs is an interactive legacy import fallback, not automatically
a replayable Nimbus import. The safest first recipe artifact is a saved triplet
loadable through home.load_prepared_data(folder, stem), or an explicit optional
validated import in the new wrapper. Do not silently replace live session data.
If live tables are changed, follow controller state/provenance conventions and
spine.mark_triplet_dirty/capture behavior; do not just assign a dataframe and
bypass GUI state tracking. No new generic pipeline/recipe language is needed.
